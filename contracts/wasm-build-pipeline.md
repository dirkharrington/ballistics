> **1.1.0 amendment:** `wasm-integration.md` §2 supersedes §2–§4 below where they conflict:
> - Staging uses `engine/stage.sh` with an explicit allowlist.
> - Both WASM executions move to `generate-sources`, so they run before the Vite build.
> - `src/main/resources/static/wasm/` is a **staging** directory consumed by Vite through `virtual:wasm-engine`. The browser loads content-hashed files from `/assets/`, never from `/wasm/`.

Builders implement this contract exactly. To change it, propose the change to the architect. Don't edit this file.

## 1. `engine/` directory layout

The `engine/` directory lives at the repository root, alongside `src/` and `pom.xml`.

```
<repo-root>/
├── engine/
│   ├── Cargo.toml          # Rust package manifest (see wasm-engine.md §1)
│   ├── Cargo.lock          # checked in; locked dependencies for reproducible CI builds
│   ├── src/
│   │   ├── lib.rs
│   │   ├── ballistics.rs
│   │   ├── atmosphere.rs
│   │   ├── drag.rs
│   │   └── types.rs
│   └── tests/
│       ├── parity_tests.rs
│       └── fixtures/        # golden JSON generated by Java engine; checked in
│           ├── 308-win-168gr.json
│           └── ...          # one file per catalog bullet
├── src/
│   └── main/
│       └── resources/
│           └── static/
│               └── wasm/    # output target; populated by mvn package or CI download
│                   ├── ballistics_engine.js
│                   ├── ballistics_engine_bg.wasm
│                   └── ballistics_engine.d.ts
├── pom.xml
└── .gitignore
```

`engine/pkg/` (wasm-pack output) and `engine/target/` (Cargo build cache) are gitignored and never committed.

## 2. `engine/loader.js` and `engine/engine.worker.js` location

These two hand-written JS files are authored in `engine/` alongside the Cargo sources and are **copied into** `src/main/resources/static/wasm/` by the Maven exec-plugin as part of the same step that copies `engine/pkg/`. They are served as static assets alongside the WASM binary.

```
engine/
├── loader.js         # hand-written ESM loader (WA-3)
└── engine.worker.js  # hand-written Web Worker (WA-5)
```

After the copy step:
```
src/main/resources/static/wasm/
├── ballistics_engine.js         # wasm-bindgen JS glue (from engine/pkg/)
├── ballistics_engine_bg.wasm    # compiled WASM binary (from engine/pkg/)
├── ballistics_engine.d.ts       # wasm-bindgen TypeScript types (from engine/pkg/)
├── loader.js                    # hand-written loader (from engine/)
└── engine.worker.js             # hand-written worker (from engine/)
```

## 3. Maven exec-maven-plugin invocation

Add the following execution to `pom.xml` inside the `<executions>` block of the `exec-maven-plugin` plugin (create the plugin entry if it does not exist):

```xml
<plugin>
  <groupId>org.codehaus.mojo</groupId>
  <artifactId>exec-maven-plugin</artifactId>
  <version>3.5.0</version>
  <executions>

    <!-- WA-1: build WASM binary from the engine/ Rust crate -->
    <execution>
      <id>wasm-pack-build</id>
      <phase>generate-resources</phase>
      <goals><goal>exec</goal></goals>
      <configuration>
        <skip>${skip.wasm.pack}</skip>
        <executable>wasm-pack</executable>
        <workingDirectory>${project.basedir}/engine</workingDirectory>
        <arguments>
          <argument>build</argument>
          <argument>--target</argument>
          <argument>web</argument>
          <argument>--release</argument>
          <argument>--out-dir</argument>
          <argument>${project.basedir}/engine/pkg</argument>
        </arguments>
      </configuration>
    </execution>

    <!-- WA-1: copy WASM output + hand-written JS files to static/ -->
    <execution>
      <id>copy-wasm-to-static</id>
      <phase>process-resources</phase>
      <goals><goal>exec</goal></goals>
      <configuration>
        <skip>${skip.wasm.pack}</skip>
        <executable>sh</executable>
        <arguments>
          <argument>-c</argument>
          <argument>mkdir -p ${project.basedir}/src/main/resources/static/wasm &amp;&amp; cp -r ${project.basedir}/engine/pkg/. ${project.basedir}/src/main/resources/static/wasm/ &amp;&amp; cp ${project.basedir}/engine/loader.js ${project.basedir}/src/main/resources/static/wasm/ &amp;&amp; cp ${project.basedir}/engine/engine.worker.js ${project.basedir}/src/main/resources/static/wasm/</argument>
        </arguments>
      </configuration>
    </execution>

  </executions>
</plugin>
```

The `${skip.wasm.pack}` property is declared in `<properties>` and defaults to `false`:

```xml
<properties>
  <!-- existing properties -->
  <skip.wasm.pack>false</skip.wasm.pack>
</properties>
```

In CI, the `java-build` job downloads the pre-built `engine/pkg/` artifact from the `rust-build` job and passes `-Dskip.wasm.pack=true` to `mvn verify`. The copy step is replaced by the explicit `cp` commands in the CI workflow (see `wasm-engine.md` §8). This prevents `java-build` from requiring the Rust toolchain while still exercising the Maven lifecycle.

> **Local development:** `mvn package` (or `mvn verify`) with no flags will run `wasm-pack build` automatically. Rust + wasm-pack must be installed locally. Run `rustup update stable && rustup target add wasm32-unknown-unknown && cargo install wasm-pack` once.

## 4. Output path mapping

| Source | Destination |
|---|---|
| `engine/pkg/ballistics_engine_bg.wasm` | `src/main/resources/static/wasm/ballistics_engine_bg.wasm` |
| `engine/pkg/ballistics_engine.js` | `src/main/resources/static/wasm/ballistics_engine.js` |
| `engine/pkg/ballistics_engine.d.ts` | `src/main/resources/static/wasm/ballistics_engine.d.ts` |
| `engine/loader.js` | `src/main/resources/static/wasm/loader.js` |
| `engine/engine.worker.js` | `src/main/resources/static/wasm/engine.worker.js` |

The `src/main/resources/static/wasm/` directory and its contents are **not committed** to the repository. They are produced at build time. Add the directory to `.gitignore` (§5).

## 6. CI cache keys

These cache entries are defined in the `rust-build` job in `.github/workflows/ci.yml` (see `wasm-engine.md` §8 for the full job spec).

| Cache purpose | `path` | `key` | `restore-keys` |
|---|---|---|---|
| Rust toolchain (`~/.rustup`) | `~/.rustup` | `${{ runner.os }}-rustup-stable` | `${{ runner.os }}-rustup-` |
| Cargo registry index + sources | `~/.cargo/registry` | `${{ runner.os }}-cargo-${{ hashFiles('engine/Cargo.lock') }}` | `${{ runner.os }}-cargo-` |
| Cargo build cache (`engine/target`) | `engine/target` | `${{ runner.os }}-cargo-target-${{ hashFiles('engine/Cargo.lock', 'engine/src/**') }}` | `${{ runner.os }}-cargo-target-` |

**Cache notes:**
- `~/.rustup` changes only when `stable` toolchain has a new release (rare); a stable key avoids thrashing.
- `Cargo.lock` is included in the registry key; a dependency update busts the cache cleanly.
- `engine/target` caches compiled dependencies but is keyed on both `Cargo.lock` and source files so a source change triggers a partial rebuild rather than a full cold build.

---

## 7. `Cargo.lock` policy

`engine/Cargo.lock` **is committed** to the repository. This matches the Rust best practice for binary crates (and mixed cdylib/rlib crates) and ensures reproducible builds in CI. The lock file is updated deliberately (`cargo update`) when dependencies need bumping, and reviewed in PRs like any other dependency change.

## 8. Local developer setup (informational — not a CI constraint)

```bash
# Install Rust (one-time)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup update stable
rustup target add wasm32-unknown-unknown

# Install wasm-pack (one-time)
cargo install wasm-pack

# Install cargo-llvm-cov for local coverage (optional)
cargo install cargo-llvm-cov

# Build everything (Rust → WASM → JAR)
mvn package

# Run Rust tests only
cargo test --manifest-path engine/Cargo.toml

# Run Rust coverage locally
cargo llvm-cov --manifest-path engine/Cargo.toml --all-features --open
```

## 9. Acceptance checklist

- [ ] `mvn package` with no flags succeeds on a machine with Rust + wasm-pack installed.
- [ ] `src/main/resources/static/wasm/` is present in the built JAR (`jar tf target/*.jar | grep wasm`).
- [ ] `mvn verify -Dskip.wasm.pack=true` succeeds when `src/main/resources/static/wasm/` is populated manually (simulating CI download).
- [ ] `engine/pkg/` is listed in `.gitignore` and absent from `git status`.
- [ ] `engine/target/` is listed in `.gitignore` and absent from `git status`.
- [ ] `src/main/resources/static/wasm/` is listed in `.gitignore` and absent from `git status`.
- [ ] `engine/Cargo.lock` is committed.
- [ ] `rust-build` CI job passes; `java-build` passes with `needs: [rust-build]` and artifact download.
- [ ] CI cache steps for `~/.rustup`, `~/.cargo/registry`, and `engine/target` each report a hit on the second run against the same `Cargo.lock`.
