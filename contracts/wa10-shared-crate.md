## 0. Summary

WA-10 restructures the `engine/` Cargo workspace into two members — `ballistics-core` (the publishable pure-Rust physics library) and `ballistics-wasm` (the WASM boundary layer). It adds `cbindgen` to generate and commit a C FFI header. No physics change, no JS API change, no JSON schema change.

**What moves:** all physics source files (`ballistics.rs`, `atmosphere.rs`, `drag.rs`, `types.rs`) move from `engine/src/` to `engine/ballistics-core/src/`. `engine/src/lib.rs` (the `#[wasm_bindgen]` glue) moves to `engine/ballistics-wasm/src/lib.rs`.

**What does not change:** the WASM binary name and exports (`compute_trajectory`, `hello_wasm`), the JS loader API, the JSON schemas, the parity tests (paths update, content unchanged), the Maven build output, the browser behavior.

### 3.2 `engine/ballistics-core/src/lib.rs`

```rust
pub mod atmosphere;
pub mod ballistics;
pub mod drag;
pub mod types;

// Re-export the public surface for downstream crates.
pub use ballistics::compute_trajectory_internal;
pub use types::{Bullet, TrajectoryParams, TrajectoryPoint, TrajectoryResult};

#[cfg(feature = "ffi")]
pub mod ffi;
```

The function `compute_trajectory_internal(params: &TrajectoryParams, bullet: &Bullet) -> Result<TrajectoryResult, String>` is extracted from the current `lib.rs`. This is a pure Rust function not decorated with `#[wasm_bindgen]`. The `ballistics-wasm` crate calls it and wraps the result in JSON.

### 3.3 `engine/ballistics-core/src/ffi.rs` (new, `#[cfg(feature = "ffi")]`)

Exact interface that cbindgen generates a header for:

```rust
use std::ffi::{CStr, CString};
use std::os::raw::c_char;
use crate::types::{Bullet, TrajectoryParams};

/// Compute a trajectory. `params_json` and `bullet_json` are UTF-8 JSON strings.
/// Returns a heap-allocated UTF-8 JSON string (TrajectoryResult or error envelope).
/// The caller must free the returned pointer with `ballistics_free_string`.
/// Returns NULL if `params_json` or `bullet_json` is NULL.
#[no_mangle]
pub unsafe extern "C" fn ballistics_compute_trajectory(
    params_json: *const c_char,
    bullet_json: *const c_char,
) -> *mut c_char {
    if params_json.is_null() || bullet_json.is_null() { return std::ptr::null_mut(); }
    let params_str = match CStr::from_ptr(params_json).to_str() { Ok(s) => s, Err(_) => return std::ptr::null_mut() };
    let bullet_str = match CStr::from_ptr(bullet_json).to_str() { Ok(s) => s, Err(_) => return std::ptr::null_mut() };
    let result = crate::ballistics::compute_trajectory_from_json(params_str, bullet_str);
    match CString::new(result) {
        Ok(cs) => cs.into_raw(),
        Err(_) => std::ptr::null_mut(),
    }
}

/// Free a string returned by `ballistics_compute_trajectory`.
/// Safe to call with NULL.
#[no_mangle]
pub unsafe extern "C" fn ballistics_free_string(s: *mut c_char) {
    if !s.is_null() { drop(CString::from_raw(s)); }
}
```

## 4. cbindgen

### 4.1 `engine/cbindgen.toml`

```toml
language = "C"
include_guard = "BALLISTICS_ENGINE_H"
documentation = true
pragma_once = false

[export]
include = ["ballistics_compute_trajectory", "ballistics_free_string"]
```

### 4.2 Header generation (CI and local)

The header is generated by:

```sh
cargo install cbindgen --version "0.27" --locked
cbindgen --config engine/cbindgen.toml \
         --crate ballistics-engine \
         --output engine/include/ballistics_engine.h \
         -- engine/ballistics-core
```

Add this as a Makefile target (`make gen-header`) and a CI step in `rust-build` (runs only when `engine/ballistics-core/src/lib.rs` or `engine/ballistics-core/src/ffi.rs` changes). The generated file is **committed** to the repository. CI fails if the committed header differs from the generated one (a "header drift" check using `git diff --exit-code engine/include/`).

## 5. wasm-pack build path update

The `wasm-pack build` command changes from:

```sh
wasm-pack build engine/ --target web
```

to:

```sh
wasm-pack build engine/ballistics-wasm --target web
```

Update: Maven `pom.xml` `wasm-pack-build` execution, `wasm-pack-build-simd` execution (WA-9), CI `rust-build` job step, local developer documentation.

The output directory `engine/pkg/` is unchanged (wasm-pack writes to `<manifest-dir>/pkg/` by default, which is now `engine/ballistics-wasm/pkg/`). To preserve the existing `engine/pkg/` path expected by `stage.sh`, add `--out-dir ../../pkg/` to the wasm-pack invocation:

```sh
wasm-pack build engine/ballistics-wasm --target web --out-dir ../../pkg
```

This keeps `engine/pkg/` as the staging source; `stage.sh` requires no path change.

## 8. Threat model delta

| STRIDE | Threat | Mitigation |
|---|---|---|
| Supply chain | `ballistics-core` published to crates.io without a pinned checksum in Cargo.lock. | Publishing is optional; the workspace always uses a `path = "../ballistics-core"` dependency from `ballistics-wasm`. External consumers of the crates.io publication must pin via `Cargo.lock`. Publish is gated to CI release workflow only, not on every merge. |
| Memory safety | C FFI (`ballistics_free_string`) can be called with a pointer not returned by `ballistics_compute_trajectory`. | `ballistics_free_string` reconstructs a `CString` from raw pointer — only safe for pointers originally produced by `into_raw()`. Document: callers must not free pointers from other allocators. Used only by iOS/Android SDKs, not by the browser. |
| Availability | iOS/Android caller double-frees the returned pointer. | Caller must nullify after `free`. Document in the generated header with `/** Must be freed exactly once */`. |

The WASM and JS surfaces are unchanged. No new browser-facing attack surface from WA-10.
